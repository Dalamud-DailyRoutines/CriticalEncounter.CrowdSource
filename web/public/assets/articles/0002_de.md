# API-Anleitung

Ein Gebiet per HTTP abonnieren und über die zurückgegebene JSON-URL den zuletzt beobachteten Zeitpunkt jedes Ereignisses abrufen. Beide Endpunkte unterstützen CORS im Browser. Alle Zeitstempel sind Unix-Sekunden in UTC.

## Abonnieren und verlängern

Eine `POST`-Anfrage mit `Content-Type: application/json` an `https://ce-crowdsource.atmoomen.top/v1/subscriptions` senden. Die Beispiel-ID durch eine aktuell auf der Website angezeigte Instanz-ID ersetzen.

```json
{
  "dataCenterID": 101,
  "instances": [{ "instanceID": 123456, "territoryID": 1252 }]
}
```

Die DC-ID steht hinter `/dc/` in der Seiten-URL. Die `territoryID` stammt aus dem [Ereigniskatalog](/assets/dynamic-event-catalog.json); `mapID` dient der Kartenanzeige. Pro Anfrage sind 1–32 verschiedene Instanz-Gebiet-Paare desselben DC möglich.

```json
{
  "dataCenterID": 101,
  "serverTime": 1788825600,
  "subscriptions": [{
    "instanceID": 123456,
    "territoryID": 1252,
    "snapshotURL": "https://ce-data.atmoomen.top/v1/events/101/123456/1252.json.js?revision=9efbf972-a6e2-4014-af55-cbe1dd318554",
    "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
    "expiresAt": 1788827400,
    "renewAfter": 1788826500
  }]
}
```

Ein Abonnement gilt 30 Minuten. Dieselbe Anfrage zum Zeitpunkt `renewAfter`, normalerweise nach 15 Minuten, erneut senden. Verbraucher teilen sich den Veröffentlichungszeitraum eines Gebiets. Eine frühe Verlängerung liefert die bisherige Frist. Nach Ablauf pausieren Aktualisierungen; ein neues Abonnement bereitet aktuelle Daten vor.

## Ereignisse lesen

Die vollständige zurückgegebene `snapshotURL` per `GET` abrufen, beispielsweise alle 30 Sekunden. Der CDN-Cache gilt 30 Sekunden. `revision` bezeichnet die Inhaltsversion, `updatedAt` deren Aktualisierungszeit.

```json
{
  "schemaVersion": 1,
  "dataCenterID": 101,
  "instanceID": 123456,
  "territoryID": 1252,
  "instanceEpoch": 1,
  "tracks": [{
    "trackID": "SouthHorn-1",
    "events": [
      { "eventType": "CE", "eventID": 33, "lastSpawnedAt": 1788825500 },
      { "eventType": "CE", "eventID": 34, "lastSpawnedAt": null }
    ]
  }],
  "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
  "updatedAt": 1788825600
}
```

Das Beispiel zeigt einen Ausschnitt; `events` enthält alle Ereignisse des Gebiets. `eventType` ist `CE` oder `FATE`. `lastSpawnedAt: null` bedeutet, dass für dieses Ereignis noch eine Beobachtung aussteht. Typ und ID verknüpfen die Daten mit Namen und Symbolen im Katalog.

Bei wiederverwendeten Instanz-IDs kann `tracks` mehrere Kandidaten enthalten. Die Gruppierung entspricht der Website; Datensätze nach `trackID` getrennt anzeigen oder auswählen. Eine leere Liste steht für bereinigte Datensätze oder ein Gebiet, für das Beobachtungen ausstehen. `instanceEpoch` ist die serverseitige Instanzgeneration.

Jeder Datensatz enthält das zuletzt beobachtete Auftreten. Neue Ereignisse, geänderte Instanzgruppen und Bereinigungen aktualisieren den Inhalt. Phasenwechsel und wiederholte Meldungen behalten die Version bei. Der Aufbewahrungszeitraum für Instanzzustände beträgt 24 Stunden seit dem Berichtsempfang. Alte URLs können gespeicherte Daten weiter ausliefern; bei der Verwendung gilt das `expiresAt` des Abonnements.

## JavaScript-Beispiel

Die Funktion beispielsweise alle 30 Sekunden aufrufen. Sie verlängert das Abonnement bei Bedarf. `serverTime` ermöglicht einen Abgleich mit der lokalen Uhr.

Browseranfragen verwenden `cache: "no-cache"`, um den lokalen Cache erneut zu validieren. Die Pfade enden auf `.json.js`; Antworten haben den Inhaltstyp `application/json`.

```javascript
const target = {
  dataCenterID: 101,
  instances: [{ instanceID: 123456, territoryID: 1252 }]
};
let subscription;

async function readEvents() {
  if (!subscription || Date.now() / 1000 >= subscription.renewAfter) {
    const response = await fetch("https://ce-crowdsource.atmoomen.top/v1/subscriptions", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(target)
    });
    if (!response.ok) throw new Error(await response.text());
    subscription = (await response.json()).subscriptions[0];
  }
  const response = await fetch(subscription.snapshotURL, { cache: "no-cache" });
  if (!response.ok) throw new Error(await response.text());
  return response.json();
}
```

## Grenzen und Fehler

Am Edge gelten 10 Abonnementanfragen pro Minute und Quell-IP sowie 64 aktive Gebiete pro DC. Gebiete desselben DC bündeln und für fortlaufende Abrufe die `snapshotURL` verwenden.

`400`: Eingaben, doppelte Paare und JSON prüfen. `404`: Instanz-ID bestätigen und nach neuen Beobachtungen erneut versuchen. `413`: Anfrage auf höchstens 4 KiB verkleinern. `429` und `503`: `Retry-After` beachten und mit Backoff wiederholen. Abgelaufene Abonnements vor weiterer Datennutzung verlängern. Die öffentliche Lese-API ist von den Zugangsdaten für Beobachtungs-Uploads getrennt.

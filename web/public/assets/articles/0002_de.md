# API-Anleitung

Ein Gebiet per HTTP-Anfrage abonnieren und anschließend den zuletzt beobachteten Zeitpunkt jedes Ereignisses über die zurückgegebene JSON-URL abrufen. Beide Endpunkte unterstützen CORS im Browser. Alle Zeitstempel sind Unix-Sekunden in UTC.

> [!WARNING]
> Bitte keine direkte WebSocket-Verbindung zur Website aufbauen; wir betrachten dies als Ressourcenmissbrauch.
> Weitere Entwicklungsanforderungen bitte über GitHub mitteilen.

## Abonnieren und verlängern

Eine `POST`-Anfrage mit `Content-Type: application/json` an `https://ce-crowdsource.atmoomen.top/v1/subscriptions` senden. Pro Anfrage sind 1–32 verschiedene Instanz-Gebiet-Paare desselben DC möglich.

```json
{
  "dataCenterID": 101,
  "instances": [{ "instanceID": 123456, "territoryID": 1252 }]
}
```

Bei erfolgreichem Abonnement lautet die Antwort:

```json
{
  "dataCenterID": 101,
  "serverTime": 1788825600,
  "subscriptions": [{
    "instanceID": 123456,
    "territoryID": 1252,
    "snapshotURL": "https://ce-data.atmoomen.top/v1/events/101/123456/1252.json.js?revision=9efbf972-a6e2-4014-af55-cbe1dd318554",
    "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
    "expiresAt": 1788827400,
    "renewAfter": 1788826500
  }]
}
```

Ein Abonnement gilt 30 Minuten. Dieselbe Anfrage zum Zeitpunkt `renewAfter`, normalerweise nach 15 Minuten, erneut senden. Verbraucher teilen sich den Veröffentlichungszeitraum eines Gebiets. Eine frühe Verlängerung liefert die bisherige Frist. Nach Ablauf pausieren Aktualisierungen; ein neues Abonnement bereitet aktuelle Daten vor. Die URL bleibt durchgehend wiederverwendbar.

## Daten lesen

Die zurückgegebene `snapshotURL` per `GET` abrufen, mit mindestens 30 Sekunden zwischen den Abrufen. Ändern sich Ereignisse, wird der Inhalt der Momentaufnahme sofort aktualisiert; der CDN-Cache gilt 30 Sekunden.

```json
{
  "schemaVersion": 1,
  "dataCenterID": 101,
  "instanceID": 123456,
  "territoryID": 1252,
  "instanceEpoch": 1,
  "tracks": [{
    "trackID": "SouthHorn-1",
    "events": [
      { "eventType": "CE", "eventID": 33, "lastSpawnedAt": 1788825500 },
      { "eventType": "CE", "eventID": 34, "lastSpawnedAt": null }
    ]
  }],
  "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
  "updatedAt": 1788825600
}
```

Die wichtigsten Felder:

| Feld | Beschreibung |
| --- | --- |
| `tracks` | Liste der Instanz-Tracks; jeder Eintrag enthält `trackID` und `events`. |
| `events` | Alle Ereignisse des Gebietskatalogs; jeder Eintrag enthält `eventType`, `eventID` und `lastSpawnedAt`. |
| `instanceEpoch` | Vom Server erkannte Instanzgeneration. |
| `revision` | Versionskennung zur Erkennung inhaltlicher Änderungen. |
| `updatedAt` | Zeitpunkt der Aktualisierung des Momentaufnahme-Inhalts. |

`eventType` ist `CE` oder `FATE`. `lastSpawnedAt: null` bedeutet, dass für dieses Ereignis in diesem Track noch eine Beobachtung aussteht. Typ und ID verknüpfen die Daten mit Namen und Symbolen im Katalog.

Bei wiederverwendeten Instanz-IDs kann `tracks` mehrere Kandidaten enthalten. Die Gruppierung entspricht der Website; Datensätze nach `trackID` getrennt anzeigen oder auswählen.

> [!WARNING]
> Eine besondere Behandlung wiederverwendeter Instanz-IDs wird nicht empfohlen, da sie höchstwahrscheinlich auf fehlerhafte Meldungen zurückgeht. Stets nur den neuesten Track verwenden.

Ein leeres `tracks`-Array steht für bereinigte Datensätze des Gebiets oder ein Gebiet, für das diese Instanz noch melden muss.

Jeder Datensatz enthält das zuletzt beobachtete Auftreten eines Ereignisses:

- Neue Auftritte, Änderungen der Instanz-Tracks und Bereinigungen aktualisieren den Inhalt; Phasenwechsel und wiederholte Meldungen behalten die bestehende Momentaufnahme bei.
- Instanzzustände werden nach dem 24-stündigen Aufbewahrungszeitraum für Meldungen bereinigt; eine alte Lese-URL kann danach weiterhin ein aufbewahrtes JSON zurückgeben.
- Bei der Nutzung der Daten gilt zusätzlich das `expiresAt` der Abonnement-Antwort.

## JavaScript-Beispiel

Die Funktion beispielsweise alle 30 Sekunden aufrufen. Sie verlängert das Abonnement bei Bedarf. `serverTime` ermöglicht einen Abgleich mit der lokalen Uhr.

```javascript
const target = {
  dataCenterID: 101,
  instances: [{ instanceID: 123456, territoryID: 1252 }]
};
let subscription;

async function readEvents() {
  if (!subscription || Date.now() / 1000 >= subscription.renewAfter) {
    const response = await fetch("https://ce-crowdsource.atmoomen.top/v1/subscriptions", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(target)
    });
    if (!response.ok) throw new Error(await response.text());
    subscription = (await response.json()).subscriptions[0];
  }
  const response = await fetch(subscription.snapshotURL, { cache: "no-cache" });
  if (!response.ok) throw new Error(await response.text());
  return response.json();
}
```

Browseranfragen verwenden `cache: "no-cache"`, um den lokalen Cache erneut zu validieren. Die Pfade enden auf `.json.js`; Antworten haben den Inhaltstyp `application/json`.

## Grenzen und Fehler

Am Edge gelten 10 Abonnementanfragen pro Minute und Quell-IP sowie 64 aktive Gebiete pro DC. Gebiete desselben DC bündeln und für fortlaufende Abrufe die `snapshotURL` verwenden. Angeforderte Instanzen müssen kürzlich auf der Website beobachtet worden sein.

| HTTP-Status | Vorgehen |
| --- | --- |
| `400` | DC-, Instanz- und Gebietsparameter, doppelte Paare und JSON-Format prüfen. |
| `404` | Instanz-ID bestätigen und erneut versuchen, sobald neue Meldungen vorliegen. |
| `413` | Anfragekörper auf höchstens 4 KiB verkleinern. |
| `429` | Gemäß `Retry-After` der Antwort warten und erneut versuchen. |
| `503` | Vorbereitung der Momentaufnahme oder Dienst vorübergehend fehlgeschlagen; gemäß `Retry-After` warten und erneut versuchen. |

Bei Fehlern mit Backoff erneut versuchen und abgelaufene Abonnements erneuern, bevor ihre Daten verwendet werden. Browseraufrufe nutzen die öffentliche API; die Zugangsdaten für Beobachtungs-Uploads verwaltet der jeweilige Client selbst.

## Zusätzliche Hinweise

Für Dalamud-Entwickler: Die hier verwendete "Instance ID" ist nicht das "Instance"-Konzept des Spiels; die "Instance ID" des Spiels dient vor allem der Instanzaufteilung überfüllter Gebiete. Im Spiel entspricht die "Instance ID" dieses Dienstes der "Zone Server ID", einem uint-Wert aus der "Server ID" (ushort, hohe Bits) und der "Instance ID" (ushort, niedrige Bits) im "Zone Init"-Paket.

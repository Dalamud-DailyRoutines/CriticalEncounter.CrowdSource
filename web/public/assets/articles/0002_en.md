# API Guide

Subscribe to an area over HTTP, then read the returned JSON URL for the most recently observed occurrence of each event. Both endpoints support browser CORS. All timestamps are UTC Unix seconds.

## Subscribe and renew

Send a `POST` request to `https://ce-crowdsource.atmoomen.top/v1/subscriptions` with `Content-Type: application/json`. Replace the example instance ID with an instance currently shown on the site.

```json
{
  "dataCenterID": 101,
  "instances": [{ "instanceID": 123456, "territoryID": 1252 }]
}
```

The DC ID appears after `/dc/` in the page URL. `instanceID` matches the instance ID shown on the site. Use the area's scalar `territoryID` from the [event catalog](/assets/dynamic-event-catalog.json); `mapID` identifies its display map. Each request accepts 1–32 distinct instance/territory pairs belonging to one DC.

```json
{
  "dataCenterID": 101,
  "serverTime": 1788825600,
  "subscriptions": [{
    "instanceID": 123456,
    "territoryID": 1252,
    "snapshotURL": "https://ce-data.atmoomen.top/v1/events/101/123456/1252.json.js?revision=9efbf972-a6e2-4014-af55-cbe1dd318554",
    "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
    "expiresAt": 1788827400,
    "renewAfter": 1788826500
  }]
}
```

Subscriptions last 30 minutes. Repeat the same request at `renewAfter`, normally after 15 minutes. Consumers share each area's publication window; early renewals return its existing expiry. Publication pauses once subscriptions expire and resumes with current data on the next subscription.

## Read event records

Send `GET` requests to the returned `snapshotURL`, preferably every 30 seconds. Reuse the complete URL. Changed records publish a new snapshot; CDN caches expire after 30 seconds. `revision` identifies a content version and `updatedAt` is its creation time.

```json
{
  "schemaVersion": 1,
  "dataCenterID": 101,
  "instanceID": 123456,
  "territoryID": 1252,
  "instanceEpoch": 1,
  "tracks": [{
    "trackID": "SouthHorn-1",
    "events": [
      { "eventType": "CE", "eventID": 33, "lastSpawnedAt": 1788825500 },
      { "eventType": "CE", "eventID": 34, "lastSpawnedAt": null }
    ]
  }],
  "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
  "updatedAt": 1788825600
}
```

The example shows an excerpt; each `events` array contains every catalog event in the area. `eventType` is `CE` or `FATE`; `lastSpawnedAt: null` indicates an event awaiting observation in that track. Match the type and ID with the catalog for names and icons.

Reused instance IDs can produce multiple candidate `tracks`, grouped exactly as on the site. Keep these groups separate and let consumers select by `trackID`. An empty array means the area's records have expired or are awaiting reports. `instanceEpoch` identifies the server's instance generation.

Each record contains the latest observed occurrence. New occurrences, track changes and cleanup update the snapshot; event phases and repeated reports retain its version. Instance state uses a 24-hour report retention window. An old URL may continue serving a retained snapshot after publication stops: observe the subscription's `expiresAt` when using the data.

## JavaScript example

Call this function from an application refresh task, typically every 30 seconds. It renews when needed and then reads the snapshot. The example uses the local clock; `serverTime` can be used to account for clock differences.

Browser requests use `cache: "no-cache"` to revalidate the local cache. Paths end in `.json.js`, and responses use the `application/json` content type.

```javascript
const target = {
  dataCenterID: 101,
  instances: [{ instanceID: 123456, territoryID: 1252 }]
};
let subscription;

async function readEvents() {
  if (!subscription || Date.now() / 1000 >= subscription.renewAfter) {
    const response = await fetch("https://ce-crowdsource.atmoomen.top/v1/subscriptions", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(target)
    });
    if (!response.ok) throw new Error(await response.text());
    subscription = (await response.json()).subscriptions[0];
  }
  const response = await fetch(subscription.snapshotURL, { cache: "no-cache" });
  if (!response.ok) throw new Error(await response.text());
  return response.json();
}
```

## Limits and errors

The subscription endpoint allows 10 requests per minute per source IP at the edge, with up to 64 active areas per DC. Batch areas in the same DC and use the snapshot URLs for ongoing reads. Requested instances must have recent observations on the site.

| HTTP status | Action |
| --- | --- |
| `400` | Check DC, instance and territory IDs, duplicate pairs and JSON syntax. |
| `404` | Confirm the instance ID and retry once recent reports are available. |
| `413` | Reduce the request body to at most 4 KiB. |
| `429` | Wait for the response's `Retry-After` interval. |
| `503` | Snapshot preparation or service access failed; retry after `Retry-After`. |

Use backoff on errors and renew expired subscriptions before using their data. These public read APIs are independent of the credentials used by observation upload clients.

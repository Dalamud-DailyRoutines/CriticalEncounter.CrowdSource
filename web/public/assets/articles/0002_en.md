# API Guide

Subscribe to an area with an HTTP request, then read each event's most recently observed occurrence from the returned JSON URL. Both endpoints support browser CORS. All timestamps are UTC Unix seconds.

> [!WARNING]
> Do not connect to the site directly over WebSocket, which we consider resource abuse.
> For further development needs, reach out through GitHub.

## Subscribe and renew

Send a `POST` request to `https://ce-crowdsource.atmoomen.top/v1/subscriptions` with `Content-Type: application/json`. Each request accepts 1–32 distinct instance/territory pairs belonging to one DC.

```json
{
  "dataCenterID": 101,
  "instances": [{ "instanceID": 123456, "territoryID": 1252 }]
}
```

Successful subscriptions return:

```json
{
  "dataCenterID": 101,
  "serverTime": 1788825600,
  "subscriptions": [{
    "instanceID": 123456,
    "territoryID": 1252,
    "snapshotURL": "https://ce-data.atmoomen.top/v1/events/101/123456/1252.json.js?revision=9efbf972-a6e2-4014-af55-cbe1dd318554",
    "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
    "expiresAt": 1788827400,
    "renewAfter": 1788826500
  }]
}
```

Subscriptions last 30 minutes. Repeat the same request at `renewAfter`, normally after 15 minutes. Consumers share each area's publication window; early renewals return its existing expiry. Publication pauses once subscriptions expire and resumes with current data on the next subscription. URLs stay reusable.

## Read data

Send `GET` requests to the returned `snapshotURL`, leaving at least 30 seconds between reads. A new snapshot publishes as soon as records change; CDN caches expire after 30 seconds.

```json
{
  "schemaVersion": 1,
  "dataCenterID": 101,
  "instanceID": 123456,
  "territoryID": 1252,
  "instanceEpoch": 1,
  "tracks": [{
    "trackID": "SouthHorn-1",
    "events": [
      { "eventType": "CE", "eventID": 33, "lastSpawnedAt": 1788825500 },
      { "eventType": "CE", "eventID": 34, "lastSpawnedAt": null }
    ]
  }],
  "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
  "updatedAt": 1788825600
}
```

Main fields:

| Field | Description |
| --- | --- |
| `tracks` | Instance track list, each item containing `trackID` and `events`. |
| `events` | Every catalog event in the area, each item containing `eventType`, `eventID` and `lastSpawnedAt`. |
| `instanceEpoch` | Instance generation as identified by the server. |
| `revision` | Version identifier used to detect content changes. |
| `updatedAt` | Time the snapshot content was updated. |

`eventType` is `CE` or `FATE`. `lastSpawnedAt: null` indicates an event awaiting observation in that track. Match the type and ID with the catalog for names and icons.

When instance IDs are reused, `tracks` can contain multiple candidate instance tracks, grouped exactly as on the site; use `trackID` to display or select each group separately.

> [!WARNING]
> Special handling for reused instance IDs is not recommended, since it most likely comes from erroneous reports. Always take only the latest track.

An empty `tracks` array means the area's records have been cleaned up, or the instance has yet to report in this area.

Each record holds the latest observed occurrence of an event:

- New occurrences, instance track changes and cleanup update the content; event phases and repeated reports retain its existing snapshot.
- Instance state is cleaned up by the 24-hour report retention window; an old read URL may still return a retained JSON afterwards.
- The subscription's `expiresAt` applies to any use of the data.

## JavaScript example

Call this function from an application refresh task, typically every 30 seconds. It renews when needed and then reads the snapshot. The example uses the local clock; `serverTime` can be used to account for clock differences.

```javascript
const target = {
  dataCenterID: 101,
  instances: [{ instanceID: 123456, territoryID: 1252 }]
};
let subscription;

async function readEvents() {
  if (!subscription || Date.now() / 1000 >= subscription.renewAfter) {
    const response = await fetch("https://ce-crowdsource.atmoomen.top/v1/subscriptions", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(target)
    });
    if (!response.ok) throw new Error(await response.text());
    subscription = (await response.json()).subscriptions[0];
  }
  const response = await fetch(subscription.snapshotURL, { cache: "no-cache" });
  if (!response.ok) throw new Error(await response.text());
  return response.json();
}
```

Browser requests use `cache: "no-cache"` to revalidate the local cache. Paths end in `.json.js`, and responses use the `application/json` content type.

## Limits and errors

The subscription endpoint allows 10 requests per minute per source IP at the edge, with up to 64 active areas per DC. Batch areas in the same DC and use the snapshot URLs for ongoing reads. Requested instances must have recent observations on the site.

| HTTP status | Action |
| --- | --- |
| `400` | Check DC, instance and territory IDs, duplicate pairs and JSON syntax. |
| `404` | Confirm the instance ID and retry once recent reports are available. |
| `413` | Reduce the request body to at most 4 KiB. |
| `429` | Wait for the response's `Retry-After` interval. |
| `503` | Snapshot preparation or service access failed; retry after `Retry-After`. |

Use backoff on errors and renew expired subscriptions before using their data. These public read APIs are independent of the credentials used by observation upload clients.

## Additional notes

For Dalamud developers, the "Instance ID" here is not the game's "Instance" concept; the game's "Instance ID" is mainly used to split crowded areas into instances. In game terms, this service's "Instance ID" corresponds to the "Zone Server ID", a uint value formed by combining the "Server ID" (ushort, high bits) and the "Instance ID" (ushort, low bits) in the "Zone Init" packet.

# Guide API

Abonnez une zone par requête HTTP, puis consultez l’URL JSON reçue pour obtenir la dernière apparition observée de chaque événement. Les deux points d’accès prennent en charge CORS. Tous les horodatages sont exprimés en secondes Unix UTC.

> [!WARNING]
> N’établissez pas de connexion WebSocket directe au site : nous la considérons comme un usage abusif des ressources.
> Pour tout autre besoin de développement, contactez-nous via GitHub.

## Abonnement et renouvellement

Envoyez une requête `POST` à `https://ce-crowdsource.atmoomen.top/v1/subscriptions` avec `Content-Type: application/json`. Une requête accepte 1 à 32 couples instance/zone distincts appartenant au même DC.

```json
{
  "dataCenterID": 101,
  "instances": [{ "instanceID": 123456, "territoryID": 1252 }]
}
```

En cas d’abonnement réussi, la réponse se présente ainsi :

```json
{
  "dataCenterID": 101,
  "serverTime": 1788825600,
  "subscriptions": [{
    "instanceID": 123456,
    "territoryID": 1252,
    "snapshotURL": "https://ce-data.atmoomen.top/v1/events/101/123456/1252.json.js?revision=9efbf972-a6e2-4014-af55-cbe1dd318554",
    "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
    "expiresAt": 1788827400,
    "renewAfter": 1788826500
  }]
}
```

L’abonnement dure 30 minutes. Répétez la même requête à `renewAfter`, généralement après 15 minutes. La période de publication d’une zone est partagée entre les consommateurs ; un renouvellement anticipé conserve l’échéance courante. À expiration, les mises à jour s’arrêtent. Un nouvel abonnement prépare les données actuelles. L’URL reste réutilisable en continu.

## Lecture des données

Effectuez un `GET` sur la `snapshotURL` reçue, en laissant au moins 30 secondes entre deux lectures. Dès qu’un événement change, le contenu de l’instantané est actualisé immédiatement ; le cache CDN dure 30 secondes.

```json
{
  "schemaVersion": 1,
  "dataCenterID": 101,
  "instanceID": 123456,
  "territoryID": 1252,
  "instanceEpoch": 1,
  "tracks": [{
    "trackID": "SouthHorn-1",
    "events": [
      { "eventType": "CE", "eventID": 33, "lastSpawnedAt": 1788825500 },
      { "eventType": "CE", "eventID": 34, "lastSpawnedAt": null }
    ]
  }],
  "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
  "updatedAt": 1788825600
}
```

Principaux champs :

| Champ | Description |
| --- | --- |
| `tracks` | Liste des pistes d’instance ; chaque entrée contient `trackID` et `events`. |
| `events` | Tous les événements du catalogue de la zone ; chaque entrée contient `eventType`, `eventID` et `lastSpawnedAt`. |
| `instanceEpoch` | Génération d’instance identifiée par le serveur. |
| `revision` | Identifiant de version servant à détecter les changements de contenu. |
| `updatedAt` | Heure de mise à jour du contenu de l’instantané. |

`eventType` vaut `CE` ou `FATE`. `lastSpawnedAt: null` indique qu’une observation reste attendue pour cet événement dans cette piste. Le type et l’identifiant permettent de retrouver noms et icônes dans le catalogue.

En cas de réutilisation d’un identifiant d’instance, `tracks` peut contenir plusieurs pistes candidates. Les groupes correspondent au site : affichez-les ou sélectionnez-les séparément par `trackID`.

> [!WARNING]
> Un traitement spécifique de la réutilisation d’un identifiant d’instance n’est pas recommandé, car elle provient très probablement de rapports erronés. Ne prenez toujours que la piste la plus récente.

Un tableau `tracks` vide signifie que les données de la zone ont été nettoyées ou que cette instance doit encore envoyer un rapport pour cette zone.

Chaque enregistrement conserve la dernière apparition observée d’un événement :

- Les nouvelles apparitions, les changements de pistes d’instance et les nettoyages actualisent le contenu ; les changements de phase et les rapports répétés conservent l’instantané existant.
- Les états d’instance sont nettoyés selon la fenêtre de conservation des rapports de 24 heures ; une ancienne URL de lecture peut encore renvoyer un JSON conservé ensuite.
- L’utilisation des données doit également respecter l’`expiresAt` de la réponse d’abonnement.

## Exemple JavaScript

Appelez cette fonction depuis une tâche de rafraîchissement, généralement toutes les 30 secondes. Elle renouvelle l’abonnement si nécessaire. `serverTime` permet de corriger un décalage de l’horloge locale.

```javascript
const target = {
  dataCenterID: 101,
  instances: [{ instanceID: 123456, territoryID: 1252 }]
};
let subscription;

async function readEvents() {
  if (!subscription || Date.now() / 1000 >= subscription.renewAfter) {
    const response = await fetch("https://ce-crowdsource.atmoomen.top/v1/subscriptions", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(target)
    });
    if (!response.ok) throw new Error(await response.text());
    subscription = (await response.json()).subscriptions[0];
  }
  const response = await fetch(subscription.snapshotURL, { cache: "no-cache" });
  if (!response.ok) throw new Error(await response.text());
  return response.json();
}
```

Les requêtes du navigateur utilisent `cache: "no-cache"` pour revalider le cache local. Les chemins se terminent par `.json.js` et les réponses utilisent le type de contenu `application/json`.

## Limites et erreurs

La limite à l’edge est de 10 requêtes d’abonnement par minute et par IP source, avec 64 zones actives par DC. Regroupez les zones d’un même DC et utilisez les `snapshotURL` pour les lectures régulières. Les instances demandées doivent avoir été observées récemment sur le site.

| Statut HTTP | Action |
| --- | --- |
| `400` | Vérifiez les paramètres DC, instance et zone, les doublons et le format JSON. |
| `404` | Confirmez l’ID d’instance et réessayez dès que des rapports récents sont disponibles. |
| `413` | Réduisez le corps de la requête à 4 KiB au maximum. |
| `429` | Attendez l’intervalle `Retry-After` indiqué dans la réponse, puis réessayez. |
| `503` | La préparation de l’instantané ou le service a échoué temporairement ; attendez `Retry-After` avant de réessayer. |

En cas d’erreur, réessayez avec un backoff et rétablissez un abonnement valide après expiration avant d’utiliser ses données. Les appels du navigateur passent par l’API publique ; les identifiants d’envoi des observations sont gérés par le client de rapport.

## Remarques complémentaires

Pour les développeurs Dalamud, l’« Instance ID » utilisée ici ne correspond pas au concept d’« Instance » du jeu ; l’« Instance ID » du jeu sert principalement à découper les zones surchargées en instances. Dans le jeu, l’« Instance ID » de ce service correspond au « Zone Server ID », une valeur uint formée en combinant le « Server ID » (ushort, bits de poids fort) et l’« Instance ID » (ushort, bits de poids faible) du paquet « Zone Init ».

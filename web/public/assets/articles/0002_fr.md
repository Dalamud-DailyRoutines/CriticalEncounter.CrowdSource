# Guide API

Abonnez une zone par HTTP, puis consultez l’URL JSON reçue pour obtenir la dernière apparition observée de chaque événement. Les deux points d’accès prennent en charge CORS. Tous les horodatages sont exprimés en secondes Unix UTC.

## Abonnement et renouvellement

Envoyez une requête `POST` à `https://ce-crowdsource.atmoomen.top/v1/subscriptions` avec `Content-Type: application/json`. Remplacez l’identifiant d’exemple par l’ID d’instance souhaité.

```json
{
  "dataCenterID": 101,
  "instances": [{ "instanceID": 123456, "territoryID": 1252 }]
}
```

Une requête accepte 1 à 32 couples instance/zone distincts appartenant au même DC.

```json
{
  "dataCenterID": 101,
  "serverTime": 1788825600,
  "subscriptions": [{
    "instanceID": 123456,
    "territoryID": 1252,
    "snapshotURL": "https://ce-data.atmoomen.top/v1/events/101/123456/1252.json.js?revision=9efbf972-a6e2-4014-af55-cbe1dd318554",
    "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
    "expiresAt": 1788827400,
    "renewAfter": 1788826500
  }]
}
```

L’abonnement dure 30 minutes. Répétez la même requête à `renewAfter`, généralement après 15 minutes. La période de publication d’une zone est partagée entre les consommateurs ; un renouvellement anticipé conserve l’échéance courante. À expiration, les mises à jour s’arrêtent. Un nouvel abonnement prépare les données actuelles. L’URL reste réutilisable en continu.

## Lecture des événements

Effectuez un `GET` sur la `snapshotURL` reçue, en laissant au moins 30 secondes entre deux lectures. Le cache CDN dure 30 secondes. `revision` identifie la version du contenu et `updatedAt` indique son heure de mise à jour.

```json
{
  "schemaVersion": 1,
  "dataCenterID": 101,
  "instanceID": 123456,
  "territoryID": 1252,
  "instanceEpoch": 1,
  "tracks": [{
    "trackID": "SouthHorn-1",
    "events": [
      { "eventType": "CE", "eventID": 33, "lastSpawnedAt": 1788825500 },
      { "eventType": "CE", "eventID": 34, "lastSpawnedAt": null }
    ]
  }],
  "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
  "updatedAt": 1788825600
}
```

L’exemple est un extrait ; chaque tableau `events` contient tous les événements de la zone. `eventType` vaut `CE` ou `FATE`. `lastSpawnedAt: null` indique une observation encore attendue pour cet événement. Le type et l’identifiant permettent de retrouver noms et icônes dans le catalogue.

La réutilisation d’un identifiant d’instance peut produire plusieurs candidats dans `tracks`. Les groupes correspondent au site : affichez-les ou sélectionnez-les séparément par `trackID`. Un tableau vide correspond à des données nettoyées ou à une zone en attente de rapports. `instanceEpoch` désigne la génération d’instance identifiée par le serveur.

Chaque événement conserve sa dernière apparition observée. Les nouvelles apparitions, changements de groupes et nettoyages mettent à jour le contenu. Les changements de phase et rapports répétés conservent sa version. Les états d’instance sont nettoyés selon une fenêtre de 24 heures depuis la réception des rapports. Une ancienne URL peut toujours servir un JSON conservé ; respectez `expiresAt` pour utiliser les données.

## Exemple JavaScript

Appelez cette fonction depuis une tâche de rafraîchissement, généralement toutes les 30 secondes. Elle renouvelle l’abonnement si nécessaire. `serverTime` permet de corriger un décalage de l’horloge locale.

Les requêtes du navigateur utilisent `cache: "no-cache"` pour revalider le cache local. Les chemins se terminent par `.json.js` et les réponses utilisent le type de contenu `application/json`.

```javascript
const target = {
  dataCenterID: 101,
  instances: [{ instanceID: 123456, territoryID: 1252 }]
};
let subscription;

async function readEvents() {
  if (!subscription || Date.now() / 1000 >= subscription.renewAfter) {
    const response = await fetch("https://ce-crowdsource.atmoomen.top/v1/subscriptions", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(target)
    });
    if (!response.ok) throw new Error(await response.text());
    subscription = (await response.json()).subscriptions[0];
  }
  const response = await fetch(subscription.snapshotURL, { cache: "no-cache" });
  if (!response.ok) throw new Error(await response.text());
  return response.json();
}
```

## Limites et erreurs

La limite à l’edge est de 10 requêtes d’abonnement par minute et par IP source, avec 64 zones actives par DC. Regroupez les zones d’un même DC et utilisez les `snapshotURL` pour les lectures régulières.

`400` : vérifiez paramètres, doublons et JSON. `404` : confirmez l’instance et réessayez après réception de rapports récents. `413` : limitez le corps à 4 KiB. `429` et `503` : respectez `Retry-After` et espacez les tentatives. Renouvelez un abonnement expiré avant de réutiliser ses données. L’API de lecture publique est indépendante des identifiants d’envoi des observations.

## Remarques complémentaires

Pour les développeurs Dalamud, l’« Instance ID » utilisée ici ne correspond pas au concept d’Instance du jeu. L’Instance ID du jeu sert principalement à découper les zones surchargées en instances ; le concept correspondant est le « Zone Server ID », une valeur uint formée en combinant le « Server ID » (ushort, bits de poids fort) et l’« Instance ID » (ushort, bits de poids faible) du paquet « Zone Init ».

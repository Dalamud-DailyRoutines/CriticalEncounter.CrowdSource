# API 이용 안내

HTTP로 지역을 구독한 뒤 반환된 JSON URL에서 각 이벤트의 최근 관측 발생 시각을 조회할 수 있습니다. 브라우저 교차 출처 요청을 지원하며 모든 타임스탬프는 UTC Unix 초 단위입니다.

## 구독 및 갱신

`https://ce-crowdsource.atmoomen.top/v1/subscriptions`로 `Content-Type: application/json`을 지정하여 `POST` 요청을 보냅니다. 예시의 `instanceID`를 사이트에 표시되는 현재 인스턴스 ID로 바꿉니다.

```json
{
  "dataCenterID": 101,
  "instances": [{ "instanceID": 123456, "territoryID": 1252 }]
}
```

DC ID는 페이지 URL의 `/dc/` 뒤에서 확인할 수 있습니다. 지역은 [이벤트 목록](/assets/dynamic-event-catalog.json)의 `territoryID`로 지정하며 `mapID`는 지도 표시용입니다. 한 요청에는 같은 DC에 속하는 서로 다른 인스턴스/지역 조합을 1~32개 넣을 수 있습니다.

```json
{
  "dataCenterID": 101,
  "serverTime": 1788825600,
  "subscriptions": [{
    "instanceID": 123456,
    "territoryID": 1252,
    "snapshotURL": "https://ce-data.atmoomen.top/v1/events/101/123456/1252.json.js?revision=9efbf972-a6e2-4014-af55-cbe1dd318554",
    "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
    "expiresAt": 1788827400,
    "renewAfter": 1788826500
  }]
}
```

구독 유효 시간은 30분입니다. 일반적으로 15분 뒤인 `renewAfter`에 같은 요청으로 갱신합니다. 같은 지역의 게시 기간은 호출자들이 공유하며 이른 갱신 요청에는 기존 만료 시각이 반환됩니다. 만료되면 갱신이 중단되고 다음 구독 시 최신 데이터가 준비됩니다.

## 이벤트 기록 조회

반환된 `snapshotURL` 전체에 `GET` 요청을 보냅니다. 권장 조회 간격과 CDN 캐시 유효 시간은 각각 30초입니다. `revision`은 내용 버전이며 `updatedAt`은 내용 갱신 시각입니다.

```json
{
  "schemaVersion": 1,
  "dataCenterID": 101,
  "instanceID": 123456,
  "territoryID": 1252,
  "instanceEpoch": 1,
  "tracks": [{
    "trackID": "SouthHorn-1",
    "events": [
      { "eventType": "CE", "eventID": 33, "lastSpawnedAt": 1788825500 },
      { "eventType": "CE", "eventID": 34, "lastSpawnedAt": null }
    ]
  }],
  "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
  "updatedAt": 1788825600
}
```

예시는 일부 이벤트만 보여 줍니다. 실제 `events`에는 해당 지역의 모든 이벤트가 포함됩니다. `eventType`은 `CE` 또는 `FATE`이며 `lastSpawnedAt: null`은 해당 이벤트의 관측을 기다리는 상태입니다. 이벤트 종류와 ID로 목록의 이름 및 아이콘을 연결할 수 있습니다.

인스턴스 ID가 재사용되면 `tracks`에 여러 후보가 나타날 수 있습니다. 사이트와 같은 그룹이므로 `trackID`별로 기록을 구분하여 표시하거나 선택합니다. 빈 배열은 기록 정리 후 또는 해당 지역의 보고를 기다리는 상태를 뜻합니다. `instanceEpoch`은 서버가 식별한 인스턴스 세대입니다.

각 기록은 마지막으로 관측된 발생 시각을 보관합니다. 새로운 발생, 인스턴스 그룹 변경 및 기록 정리가 내용을 갱신하며 단계 변화와 반복 보고는 기존 버전을 유지합니다. 인스턴스 상태는 보고 수신 후 24시간 보관 기준에 따라 정리됩니다. 만료된 URL에서도 보관된 JSON이 반환될 수 있으므로 데이터 사용 시 구독의 `expiresAt`을 지켜야 합니다.

## JavaScript 예제

일반적으로 30초마다 실행되는 새로 고침 작업에서 다음 함수를 호출합니다. 필요할 때 구독을 갱신하며 로컬 시계 차이는 `serverTime`으로 보정할 수 있습니다.

브라우저 요청은 `cache: "no-cache"`로 로컬 캐시를 재검증합니다. 경로는 `.json.js`로 끝나며 응답 콘텐츠 유형은 `application/json`입니다.

```javascript
const target = {
  dataCenterID: 101,
  instances: [{ instanceID: 123456, territoryID: 1252 }]
};
let subscription;

async function readEvents() {
  if (!subscription || Date.now() / 1000 >= subscription.renewAfter) {
    const response = await fetch("https://ce-crowdsource.atmoomen.top/v1/subscriptions", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(target)
    });
    if (!response.ok) throw new Error(await response.text());
    subscription = (await response.json()).subscriptions[0];
  }
  const response = await fetch(subscription.snapshotURL, { cache: "no-cache" });
  if (!response.ok) throw new Error(await response.text());
  return response.json();
}
```

## 제한 및 오류 처리

에지에서 원본 IP별 구독 요청은 분당 10회이며 DC별 동시 활성 지역은 최대 64개입니다. 같은 DC의 지역을 묶어 구독하고 지속적인 조회에는 `snapshotURL`을 사용합니다.

`400`: 매개변수, 중복 조합, JSON을 확인합니다. `404`: 인스턴스 ID를 확인하고 최근 보고가 도착한 후 재시도합니다. `413`: 요청 본문을 4 KiB 이하로 줄입니다. `429` 및 `503`: `Retry-After`에 따라 기다린 뒤 재시도 간격을 늘립니다. 만료된 구독은 데이터를 사용하기 전에 갱신합니다. 공개 읽기 API와 관측 업로드 인증 정보는 별도로 관리됩니다.

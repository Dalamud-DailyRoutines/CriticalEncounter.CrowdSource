# API 이용 안내

HTTP 요청으로 지역을 구독한 뒤 반환된 JSON URL에서 각 이벤트의 최근 관측 발생 시각을 조회할 수 있습니다. 브라우저 교차 출처 요청을 지원하며 모든 타임스탬프는 UTC Unix 초 단위입니다.

> [!WARNING]
> WebSocket으로 사이트에 직접 연결하지 마십시오. 리소스 남용으로 간주합니다.
> 추가 개발 요구 사항은 GitHub로 문의해 주십시오.

## 구독 및 갱신

`https://ce-crowdsource.atmoomen.top/v1/subscriptions`로 `Content-Type: application/json`을 지정하여 `POST` 요청을 보냅니다. 한 요청에는 같은 DC에 속하는 서로 다른 인스턴스/지역 조합을 1~32개 넣을 수 있습니다.

```json
{
  "dataCenterID": 101,
  "instances": [{ "instanceID": 123456, "territoryID": 1252 }]
}
```

구독에 성공한 응답 형식은 다음과 같습니다.

```json
{
  "dataCenterID": 101,
  "serverTime": 1788825600,
  "subscriptions": [{
    "instanceID": 123456,
    "territoryID": 1252,
    "snapshotURL": "https://ce-data.atmoomen.top/v1/events/101/123456/1252.json.js?revision=9efbf972-a6e2-4014-af55-cbe1dd318554",
    "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
    "expiresAt": 1788827400,
    "renewAfter": 1788826500
  }]
}
```

구독 유효 시간은 30분입니다. 일반적으로 15분 뒤인 `renewAfter`에 같은 요청으로 갱신합니다. 같은 지역의 게시 기간은 호출자들이 공유하며 이른 갱신 요청에는 기존 만료 시각이 반환됩니다. 만료되면 갱신이 중단되고 다음 구독 시 최신 데이터가 준비됩니다. URL은 계속 재사용할 수 있습니다.

## 데이터 조회

반환된 `snapshotURL`에 `GET` 요청을 보냅니다. 조회 간격은 30초 이상으로 유지합니다. 기록이 바뀌면 스냅샷 내용이 곧바로 갱신됩니다. CDN 캐시 유효 시간은 30초입니다.

```json
{
  "schemaVersion": 1,
  "dataCenterID": 101,
  "instanceID": 123456,
  "territoryID": 1252,
  "instanceEpoch": 1,
  "tracks": [{
    "trackID": "SouthHorn-1",
    "events": [
      { "eventType": "CE", "eventID": 33, "lastSpawnedAt": 1788825500 },
      { "eventType": "CE", "eventID": 34, "lastSpawnedAt": null }
    ]
  }],
  "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
  "updatedAt": 1788825600
}
```

주요 필드는 다음과 같습니다.

| 필드 | 설명 |
| --- | --- |
| `tracks` | 인스턴스 트랙 목록이며 각 항목은 `trackID`와 `events`를 포함합니다. |
| `events` | 해당 지역 목록의 모든 이벤트이며 각 항목은 `eventType`, `eventID`, `lastSpawnedAt`을 포함합니다. |
| `instanceEpoch` | 서버가 식별한 인스턴스 세대입니다. |
| `revision` | 내용 변경 여부를 판단하는 버전 식별자입니다. |
| `updatedAt` | 스냅샷 내용이 갱신된 시각입니다. |

`eventType`은 `CE` 또는 `FATE`입니다. `lastSpawnedAt: null`은 해당 트랙에서 이벤트 관측을 기다리는 상태입니다. 이벤트 종류와 ID로 목록의 이름 및 아이콘을 연결할 수 있습니다.

인스턴스 ID가 재사용되면 `tracks`에 여러 후보가 나타날 수 있습니다. 그룹은 사이트와 같으므로 `trackID`별로 기록을 구분하여 표시하거나 선택합니다.

> [!WARNING]
> 인스턴스 ID 재사용에 대한 특별한 처리는 권장하지 않습니다. 잘못된 보고에서 비롯되었을 가능성이 높기 때문입니다. 항상 최신 track만 사용하십시오.

`tracks`가 비어 있으면 해당 지역의 기록이 정리되었거나 이 지역의 보고를 기다리는 상태입니다.

각 기록은 마지막으로 관측된 발생 시각을 보관합니다.

- 새로운 발생 기록, 인스턴스 트랙 변화, 기록 정리가 내용을 갱신합니다. 이벤트 단계 변화와 반복 보고는 기존 스냅샷을 유지합니다.
- 인스턴스 상태는 보고 수신 후 24시간 보관 기간에 따라 정리되며, 만료된 뒤에도 이전 조회 주소가 보관된 JSON을 반환할 수 있습니다.
- 데이터를 사용할 때는 구독 응답의 `expiresAt`도 함께 지켜야 합니다.

## JavaScript 예제

일반적으로 30초마다 실행되는 새로 고침 작업에서 다음 함수를 호출합니다. 필요할 때 구독을 갱신하며 로컬 시계 차이는 `serverTime`으로 보정할 수 있습니다.

```javascript
const target = {
  dataCenterID: 101,
  instances: [{ instanceID: 123456, territoryID: 1252 }]
};
let subscription;

async function readEvents() {
  if (!subscription || Date.now() / 1000 >= subscription.renewAfter) {
    const response = await fetch("https://ce-crowdsource.atmoomen.top/v1/subscriptions", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(target)
    });
    if (!response.ok) throw new Error(await response.text());
    subscription = (await response.json()).subscriptions[0];
  }
  const response = await fetch(subscription.snapshotURL, { cache: "no-cache" });
  if (!response.ok) throw new Error(await response.text());
  return response.json();
}
```

브라우저 요청은 `cache: "no-cache"`로 로컬 캐시를 재검증합니다. 경로는 `.json.js`로 끝나며 응답 콘텐츠 유형은 `application/json`입니다.

## 제한 및 오류 처리

에지에서 원본 IP별 구독 요청은 분당 10회이며 DC별 동시 활성 지역은 최대 64개입니다. 같은 DC의 지역을 묶어 구독하고 지속적인 조회에는 `snapshotURL`을 사용합니다. 일괄 요청에 넣는 인스턴스는 사이트에서 최근에 관측된 것이어야 합니다.

| HTTP 상태 | 처리 방법 |
| --- | --- |
| `400` | DC, 인스턴스, 지역 매개변수와 중복 조합, JSON 형식을 확인합니다. |
| `404` | 해당 인스턴스의 최근 기록이 아직 보고되지 않았습니다. 인스턴스 ID를 확인하고 나중에 다시 시도합니다. |
| `413` | 요청 본문이 4 KiB를 초과했습니다. 배치를 줄입니다. |
| `429` | 응답의 `Retry-After`에 따라 기다린 뒤 다시 시도합니다. |
| `503` | 스냅샷 준비 또는 서비스가 일시적으로 실패했습니다. `Retry-After`에 따라 기다린 뒤 다시 시도합니다. |

오류가 발생하면 백오프로 다시 시도하고, 구독이 만료되면 유효한 구독을 다시 만든 뒤 데이터를 사용합니다. 브라우저 호출은 공개 API를 사용하며, 관측 보고 업로드에 쓰는 인증 정보는 보고 클라이언트가 따로 관리합니다.

## 추가 설명

Dalamud 개발자라면 여기서 말하는 “Instance ID”는 게임의 “Instance” 개념과 다릅니다. 게임의 “Instance ID”는 주로 혼잡한 지역의 인스턴스 분할에 사용됩니다. 이 서비스의 “Instance ID”가 게임에서 대응하는 개념은 “Zone Server ID”이며, “Zone Init” 패킷의 “Server ID”(ushort, 상위 비트)와 “Instance ID”(ushort, 하위 비트)를 결합한 uint 값입니다.

# API 利用ガイド

HTTP でエリアを購読し、返された JSON URL から各イベントの直近の観測時刻を取得できます。ブラウザーのクロスオリジンアクセスに対応しています。時刻はすべて UTC の Unix 秒です。

## 購読と更新

`https://ce-crowdsource.atmoomen.top/v1/subscriptions` に `Content-Type: application/json` を指定して `POST` します。例の `instanceID` は、サイトに表示されているインスタンス ID に置き換えてください。

```json
{
  "dataCenterID": 101,
  "instances": [{ "instanceID": 123456, "territoryID": 1252 }]
}
```

DC ID はページ URL の `/dc/` の後に表示されます。エリアは[イベント一覧](/assets/dynamic-event-catalog.json)の `territoryID` で指定します。`mapID` は地図表示用です。1 回のリクエストで、同じ DC の異なるインスタンス・エリアの組み合わせを 1～32 件指定できます。

```json
{
  "dataCenterID": 101,
  "serverTime": 1788825600,
  "subscriptions": [{
    "instanceID": 123456,
    "territoryID": 1252,
    "snapshotURL": "https://ce-data.atmoomen.top/v1/events/101/123456/1252.json.js?revision=9efbf972-a6e2-4014-af55-cbe1dd318554",
    "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
    "expiresAt": 1788827400,
    "renewAfter": 1788826500
  }]
}
```

購読は 30 分間有効です。通常は 15 分後の `renewAfter` に同じリクエストを送信して更新します。同じエリアの配信期間は利用者間で共有され、早い更新には現在の有効期限が返ります。期限が切れると配信更新が停止し、次回の購読時に最新データを準備します。

## イベント記録の取得

返された `snapshotURL` 全体を使って `GET` します。取得間隔の目安は 30 秒です。CDN のキャッシュ期間も 30 秒です。`revision` は内容のバージョン、`updatedAt` は内容の更新時刻です。

```json
{
  "schemaVersion": 1,
  "dataCenterID": 101,
  "instanceID": 123456,
  "territoryID": 1252,
  "instanceEpoch": 1,
  "tracks": [{
    "trackID": "SouthHorn-1",
    "events": [
      { "eventType": "CE", "eventID": 33, "lastSpawnedAt": 1788825500 },
      { "eventType": "CE", "eventID": 34, "lastSpawnedAt": null }
    ]
  }],
  "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
  "updatedAt": 1788825600
}
```

例では一部のイベントを抜粋しています。実際の `events` にはエリア内の全イベントが含まれます。`eventType` は `CE` または `FATE` で、`lastSpawnedAt: null` はそのイベントの観測待ちを表します。名前とアイコンはイベントの種類と ID で一覧に関連付けられます。

インスタンス ID の再利用により `tracks` に複数の候補が現れる場合があります。サイトと同じグループを `trackID` ごとに表示・選択してください。空の配列は記録の整理後、またはそのエリアの報告待ちを表します。`instanceEpoch` はサーバーが識別するインスタンス世代です。

各記録は最後に観測された発生時刻を保持します。新しい発生、インスタンスの変化、記録の整理によって更新されます。イベント段階や同じ報告の再送ではバージョンを維持します。インスタンス状態は報告の受信から 24 時間を基準に整理されます。古い URL が保存済み JSON を返す場合もあるため、データの利用期限には購読の `expiresAt` を使用してください。

## JavaScript の例

この関数を通常 30 秒ごとの更新処理から呼び出します。必要に応じて購読を更新します。時刻差はレスポンスの `serverTime` で補正できます。

ブラウザーからの取得には `cache: "no-cache"` を指定し、ローカルキャッシュを再検証します。パスの末尾は `.json.js`、レスポンスの Content-Type は `application/json` です。

```javascript
const target = {
  dataCenterID: 101,
  instances: [{ instanceID: 123456, territoryID: 1252 }]
};
let subscription;

async function readEvents() {
  if (!subscription || Date.now() / 1000 >= subscription.renewAfter) {
    const response = await fetch("https://ce-crowdsource.atmoomen.top/v1/subscriptions", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(target)
    });
    if (!response.ok) throw new Error(await response.text());
    subscription = (await response.json()).subscriptions[0];
  }
  const response = await fetch(subscription.snapshotURL, { cache: "no-cache" });
  if (!response.ok) throw new Error(await response.text());
  return response.json();
}
```

## 制限とエラー

購読はエッジで送信元 IP ごとに毎分 10 回、DC ごとに同時 64 エリアまでです。同じ DC のエリアをまとめ、継続的な取得には `snapshotURL` を使用します。

`400`：入力・重複・JSON を確認。`404`：インスタンス ID を確認し、直近の報告が届いてから再試行。`413`：本文を 4 KiB 以下に分割。`429` と `503`：`Retry-After` に従って待機し、バックオフ付きで再試行。期限切れの購読はデータ利用前に更新してください。公開読み取り API と観測データのアップロード認証は独立しています。

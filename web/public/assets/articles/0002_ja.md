# API 利用ガイド

HTTP リクエストでエリアを購読し、返された JSON URL から各イベントの直近の観測時刻を取得できます。ブラウザーのクロスオリジンアクセスに対応しています。時刻はすべて UTC の Unix 秒です。

> [!WARNING]
> WebSocket でサイトへ直接接続しないでください。リソースの濫用とみなします。
> さらなる開発のご要望は GitHub からご連絡ください。

## 購読と更新

`https://ce-crowdsource.atmoomen.top/v1/subscriptions` に `Content-Type: application/json` を指定して `POST` します。1 回のリクエストで、同じ DC の異なるインスタンス・エリアの組み合わせを 1～32 件指定できます。

```json
{
  "dataCenterID": 101,
  "instances": [{ "instanceID": 123456, "territoryID": 1252 }]
}
```

購読が成功した場合のレスポンスは次のとおりです。

```json
{
  "dataCenterID": 101,
  "serverTime": 1788825600,
  "subscriptions": [{
    "instanceID": 123456,
    "territoryID": 1252,
    "snapshotURL": "https://ce-data.atmoomen.top/v1/events/101/123456/1252.json.js?revision=9efbf972-a6e2-4014-af55-cbe1dd318554",
    "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
    "expiresAt": 1788827400,
    "renewAfter": 1788826500
  }]
}
```

購読は 30 分間有効です。通常は 15 分後の `renewAfter` に同じリクエストを送信して更新します。同じエリアの配信期間は利用者間で共有され、早い更新には現在の有効期限が返ります。期限が切れると配信更新が停止し、次回の購読時に最新データを準備します。URL は継続して再利用できます。

## データの取得

返された `snapshotURL` に `GET` します。取得間隔は 30 秒以上あけてください。記録が変化すると、スナップショットの内容はすぐに更新されます。CDN のキャッシュ期間は 30 秒です。

```json
{
  "schemaVersion": 1,
  "dataCenterID": 101,
  "instanceID": 123456,
  "territoryID": 1252,
  "instanceEpoch": 1,
  "tracks": [{
    "trackID": "SouthHorn-1",
    "events": [
      { "eventType": "CE", "eventID": 33, "lastSpawnedAt": 1788825500 },
      { "eventType": "CE", "eventID": 34, "lastSpawnedAt": null }
    ]
  }],
  "revision": "9efbf972-a6e2-4014-af55-cbe1dd318554",
  "updatedAt": 1788825600
}
```

主なフィールドは次のとおりです。

| フィールド | 説明 |
| --- | --- |
| `tracks` | インスタンストラックの一覧。各項目は `trackID` と `events` を含みます。 |
| `events` | エリア内の全イベント。各項目は `eventType`、`eventID`、`lastSpawnedAt` を含みます。 |
| `instanceEpoch` | サーバーが識別するインスタンス世代。 |
| `revision` | 内容の変化を判定するためのバージョン識別子。 |
| `updatedAt` | スナップショットの内容が更新された時刻。 |

`eventType` は `CE` または `FATE` です。`lastSpawnedAt: null` は、そのトラックで該当イベントの観測を待っている状態を表します。名前とアイコンはイベントの種類と ID で一覧に関連付けられます。

インスタンス ID が再利用されると、`tracks` に複数の候補が現れる場合があります。グループはサイトと同じなので、`trackID` ごとに記録を分けて表示または選択してください。

> [!WARNING]
> インスタンス ID の再利用に特別な処理を加えることは推奨しません。誤った報告に由来する可能性が高いためです。常に最新の track のみを使用してください。

`tracks` が空の場合は、そのエリアの記録が整理済みであるか、このエリアでの報告を待っている状態です。

各記録は最後に観測された発生時刻を保持します。

- 新しい発生記録、インスタンストラックの変化、記録の整理によって内容が更新されます。イベント段階の変化や同じ報告の再送では既存のスナップショットを維持します。
- インスタンス状態は報告の受信から 24 時間の保持期間で整理されます。期限切れ後の古い URL が保存済み JSON を返す場合もあります。
- データの利用時は、購読レスポンスの `expiresAt` にも従ってください。

## JavaScript の例

この関数を通常 30 秒ごとの更新処理から呼び出します。必要に応じて購読を更新します。時刻差はレスポンスの `serverTime` で補正できます。

```javascript
const target = {
  dataCenterID: 101,
  instances: [{ instanceID: 123456, territoryID: 1252 }]
};
let subscription;

async function readEvents() {
  if (!subscription || Date.now() / 1000 >= subscription.renewAfter) {
    const response = await fetch("https://ce-crowdsource.atmoomen.top/v1/subscriptions", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(target)
    });
    if (!response.ok) throw new Error(await response.text());
    subscription = (await response.json()).subscriptions[0];
  }
  const response = await fetch(subscription.snapshotURL, { cache: "no-cache" });
  if (!response.ok) throw new Error(await response.text());
  return response.json();
}
```

ブラウザーからの取得には `cache: "no-cache"` を指定し、ローカルキャッシュを再検証します。パスの末尾は `.json.js`、レスポンスの Content-Type は `application/json` です。

## 制限とエラー

購読はエッジで送信元 IP ごとに毎分 10 回、DC ごとに同時 64 エリアまでです。同じ DC のエリアをまとめ、継続的な取得には `snapshotURL` を使用します。一括リクエストに含めるインスタンスは、サイトで直近に観測されたものにしてください。

| HTTP ステータス | 対処 |
| --- | --- |
| `400` | DC・インスタンス・エリアのパラメーター、重複する組み合わせ、JSON 形式を確認します。 |
| `404` | 指定したインスタンスの直近の記録がまだ報告されていません。インスタンス ID を確認し、後で再試行します。 |
| `413` | リクエスト本文が 4 KiB を超えています。バッチを小さくします。 |
| `429` | レスポンスの `Retry-After` に従って待機してから再試行します。 |
| `503` | スナップショットの準備またはサービスが一時的に失敗しました。`Retry-After` に従って待機してから再試行します。 |

エラー時はバックオフ付きで再試行し、購読が期限切れになったら有効な購読を再取得してからデータを使用してください。ブラウザーからの呼び出しは公開 API を利用します。観測データのアップロードに使う認証情報は、報告クライアントが別途管理します。

## 補足

Dalamud の開発者であれば、ここでいう「Instance ID」はゲームの「Instance」とは別の概念です。ゲームの「Instance ID」は主に混雑したエリアのインスタンス分割に使われます。本サービスの「Instance ID」がゲーム内で対応する概念は「Zone Server ID」で、「Zone Init」パケット内の「Server ID」（ushort、上位ビット）と「Instance ID」（ushort、下位ビット）を結合した uint 値です。
